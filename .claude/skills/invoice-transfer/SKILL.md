# 平台發票辨識轉入

把 `平台發票-114-X.xlsx` 裡**內嵌在工作表中的發票圖片**（不是儲存格資料）辨識出來，
算好未稅金額，寫進 `發票整理記錄_yymmdd.xlsx` 的「發票明細」工作表。

| 用途 | 路徑 |
|------|------|

| 進度筆記 | `E:\88. Claude\00_claude data\發票整理筆記.md` |

## 輸出檔命名

資料以**累加**方式寫入同一檔案，依月份順序逐月追加。

- **進行中**（全年未完成）：`發票整理記錄_yymmdd.xlsx`，`yymmdd` = 當天處理日期
  - 例：`發票整理記錄_260604.xlsx`
- **全年完成後**：改名為 `發票整理記錄_yyyy.xlsx`，`yyyy` = 發票所屬西元年
  - 例：`發票整理記錄_2025.xlsx`

## 寫入哪張工作表

輸出檔有 `1月明細`～`12月明細` 共 12 張，**依發票日期的月份**寫入對應工作表。
檔名的 `114-N` 就是 ROC 114 年的第 N 月，對應 `N月明細`：

| 來源檔 | 寫入 |
|--------|------|
| 平台發票-114-1.xlsx | 1月明細 |
| 平台發票-114-2.xlsx | 2月明細 |
| 平台發票-114-3.xlsx | 3月明細 |

FoodPanda 發票的**費用期間**常跨到上個月（例如 3 月的發票涵蓋 2/16~2/28），
一律以**發票日期**決定放哪張工作表，不是以費用期間。

## 欄位結構（各月明細工作表）

| 欄 | 欄位 | 來源 |
|----|------|------|
| A | 賣方名稱 | 圖片 |
| B | 賣方統編 | 圖片 |
| C | 買方名稱 | 由 D 欄統編比對 NameList |
| D | 買方統編 | 圖片 |
| E | 發票號碼 | 圖片 |
| F | 發票日期 | 圖片（datetime，格式 yyyy/m/d） |
| G | 交易日期（費用期間） | 圖片（文字） |
| H | 總計 | 計算 = I + J |
| I | **稅額** | 圖片 |
| J | **應稅銷售額** | 圖片 |
| K | Uber費用 未稅金額 | 計算 = J − 其他所有品項 |
| L | 廣告費用 未稅金額 | 計算 |
| M | 附加服務費 未稅金額 | 計算 |
| N~T | 品項 4~10 未稅金額 | 計算 |

> ⚠️ **I 是稅額、J 是應稅銷售額**，不要寫反。發票圖片上的排列順序是
> 「銷售額(應稅) → 稅額 → 總計」，與 Excel 欄位順序相反。

## 計算規則

```
品項未稅 = round(含稅 / 1.05)
K（Uber費用未稅） = J − 其他所有品項未稅     ← 用差額回推，確保 K+L+M = J
H = I + J
```

**K 一定要用差額回推**，不要各自 round 後相加，否則會因為進位造成 K+L+M ≠ J。

FoodPanda 發票通常只有「佣金」單一品項 → 全額歸 K（即 K = J），L/M 留空。

## 執行流程

xlsx 本質是 zip，發票圖片存在 `xl/media/`。

1. **解壓提取圖片** — 把 xlsx 當 zip 解開，取出 `xl/media/` 下的發票影像到暫存資料夾
2. **批量讀圖辨識** — 一次讀 12 張以上，直接整理數據，不要逐張列出說明
3. **計算未稅金額** — 依上面的計算規則，Uber 費用用差額回推
4. **寫入發票整理記錄** — 一次性寫入，不要逐列寫
5. **二次讀圖比對驗證** — 重新讀圖核對已寫入的資料
6. **有差異則修正** — 修正後再比對，直到完全正確
7. **套用格式** — 見下方格式設定
8. **清理暫存圖片**
9. **歸檔** — 整個 xlsx 的**所有工作表**都處理完成後，才把來源檔移到 `completed rawdata\`
10. **更新筆記**（僅使用者明確說「儲存」時才執行）— 更新 `發票整理筆記.md` 的完成進度表。
    預設「執行」流程只寫入主檔 `發票整理記錄_yymmdd.xlsx`，不主動更新筆記

## 格式設定

Excel 對齊常數：

```
xlLeft   = -4131
xlRight  = -4152
xlCenter = -4108
```

- **標題列**：置中 + 粗體
- **A~G 欄**：靠左（含 F 發票日期、G 交易日期）
- **H~T 欄**：靠右（數字金額欄）

## 執行準則

使用者說「**執行**」= 轉入發票資料，一次性完成所有工作表。

- ✓ 不須列出圖片及說明，直接整理數據
- ✓ 執行中所有權限都已授予，直接操作，無需詢問
- ✓ 不須再詢問使用者確認，直接執行完成
- ✓ 跨年規則：若發票跨年，先 copy 舊檔保留 → 清空原檔資料 → 輸入新年度資料

減少中間詢問可提升速度 3–5 倍。

## 二次驗證怎麼做才有效

算術檢核（`I+J=H`、品項含稅合計 `=H`）能抓出金額誤讀，但**抓不到發票號碼、
日期的誤讀** — 那些不參與運算。所以步驟 5 的二次讀圖不能省。

原圖只有約 159×401 px，直接讀容易誤判相近數字（實測發生過 `15099` 讀成 `15009`、
`LY-97734077` 讀成 `LY-97743077`）。有效做法：

1. 用 PIL 把圖放大 2.5~3 倍（`Image.LANCZOS`）
2. 每 6 張橫向拼成一張對照圖並標上編號
3. 重讀拼版圖，逐欄比對已寫入的資料

金額欄先跑算術檢核，號碼與日期欄靠拼版重讀，兩者合起來才算驗證完成。
